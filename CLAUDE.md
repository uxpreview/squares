# Goose at Large: notes for AI agents

Goose at Large (the repo, the folder, the address and the saves' keys still say squares) is an isometric hidden-object game drawn entirely on a 2D canvas. Vanilla JS modules, built with Vite. No frameworks, no runtime dependencies (fonts are the only npm packages that ship).

The owner is a designer who vibe codes. Explain changes in plain language, say where to change things, and don't hand them a stack trace to debug.

## Plans

- `docs/STRATEGY.md`: where the game is going and why (session 8): the goals in order, v2 before new places, a verb per place, the difficulty proposal, the rename to Goose at Large. Read it before planning a session.
- `docs/ROADMAP.md`: what's being built and in what order, one PR per session. Read it at the start of a session; update it at the end (tick what shipped, record decisions).
- `docs/PROCESS.md`: how a level gets made (brief, greybox, parallel area art, art direction, QA, preview), who does what, and the quality bar. Follow it for every new level.
- `docs/levels/<id>.md`: each level's brief, the single source of truth for that level. Read it before touching the level; write decisions back into it.
- `docs/LEVELS.md`: the level backlog, with a pitch per idea and what engine pieces each needs.
- `docs/INSPIRATION.md`: the owner's reference images, described (the images aren't stored), and what each teaches. Every new place starts from here.

## Commands

- First time on a computer: `npm install`, then `npx playwright install chromium` (the tools' browser). See "New computer setup" in the README. Playwright is pinned to 1.61 for macOS 13; don't raise it without checking the owner's Mac.
- `npm run dev` to play locally.
- `npm run build` must pass before you push.
- `npm run smoke` clicks through title, picker, play, finding, finishing, old save migration and deep links. Run it after touching `src/engine/`, `src/game/`, `src/ui/`, `src/main.js`, `index.html` or `styles.css`. Add a check when you add a flow.
- `node tools/shoot.mjs <target> <out.png> [--mobile] [--landscape] [--zoom=2] [--t=4] [--at=90] [--freeze] [--storey=up] [--finds] [--eval="js"]` to look at your work. Targets: `title`, `maps`, a map id (`block`), or `map/zone` (`block/pool`). `--at` shows a moment of the scene (seconds), `--freeze` stops the clock right on it (to catch a flash of lightning), `--storey` a floor, `--finds` rings every find, `--eval` sets up a state first. Always look at desktop and `--mobile`.
- `node tools/tour.mjs <map>/<zone> [--zoom=3] [--at=55,165,300]` tiles an area pinched in on a phone, the way a player looks around (into `qa-out/tour/`). Look at every tile before art direction ends and before gate 3: an area's own framing hides greybox props, people drawn inside furniture and seams.
- `npm run new-level -- <id>` scaffolds a new place from its brief (`docs/levels/<id>.md`).
- `npm run qa -- <id>` runs every machine check on a place and makes its contact sheet in `qa-out/<id>/` (ignored by git). It must pass before a level goes to the owner. `--quick` skips the slow parts.
- `node tools/fps.mjs <id>` counts real frames per second in every view, in a visible window on this computer's graphics chip. QA's speed check can't see graphics-chip lag; run this after changing how things are drawn. `--only=a,b` for some views, `--eval="js"` to switch something off first and compare, `--auto` to let sharpness step down on slow frames as it does for players (tools keep one sharpness otherwise).
- `node tools/covered.mjs <id> --shots` lists people drawn inside solid things and finds painted over by their furniture, with close-ups (QA runs it as `covered`, as warnings with the close-ups on the contact sheet). Look at each: behind a post is fine, inside a counter isn't.
- `node tools/sound.mjs [<id>]` measures every bed, a place's mix in every area at a dozen hours, and its cues against a honk (QA runs the same check). Run it after touching `src/game/audio.js`, `beds.js` or a place's `sound.js`.
- `npm run build && node tools/load.mjs` times the title on a slow phone connection (slow 4G, a 4x slower processor). It should stay under a second.
- `node tools/playtest.mjs <id> prepare|check` runs a blind playtest from screenshots (see `docs/prompts/playtester.md`).
- `node tools/icons.mjs` redraws the app icons and `favicon.ico` from `public/favicon.svg`.
- `docs/AWWWARDS.md` is the Developer Award checklist (semantics, animations, accessibility, speed, responsive, markup) with the last measured numbers and how to re-run each audit. Re-run them after big changes to the page or the first load.

## Architecture (see README for the file map)

- **Places (maps) are made of zones.** A map file (`src/maps/<id>/map.js`) lists zone modules and where they sit in 3D (`at: [x, y, z]`, zones are 16 x 16), plus its cutaway mode, copy (`words`) and optional `backdrop`/`sky` art. `src/maps/index.js` registers maps with lazy `load()` imports.
- **Houses:** a map can name `storeys` (a lift panel in the corner changes floors; one shows at a time), drop inside walls to waist height (`cutaway.walls`; zones draw their walls with `R.walls` so the engine can cut them), and run `walkers`: people on one clock who walk room to room through doors, drawn by whichever zone they're in (`schedule()` in `engine/actors.js`). Its `stairs` can be tapped too: on the whole house they change floors, in a room they take you to the room at the other end. Rooms can go dark (`R.dark`) and light up (`R.light`). The Manor uses all of it.
- **Each new level has a style sheet** (`src/maps/<id>/style.js`): its inks, shared props, and shared state like the storm.
- **A first visit is invited in.** Until you step into a room, a card pinned to one says where to start (`invite`, `words.invite` and `words.hint` in the map), with a ring where to tap. On a goose map, rooms that still hide their goose honk now and then on the overview; a whodunit's goose stays quiet.
- **The map is the screen.** The camera has soft edges (`camera.range`, from the map box `play.js` gives it): drag past one and it gives, let go and it springs back, and flights land inside, so nobody loses the map. On a phone the overview fills the screen: a map's `overview(portrait, storey, short)` returns the box to frame, narrowed on the axis that should run off the edges (see `block/map.js`); the default in `world.js` fills an upright phone's height. A place opens with its floors already where they belong and fades in; nothing drops or bounces.
- **Streets and days** (the Block Party, `src/maps/block/`): an area of any shape (a street) that's longer than a room is framed a room's worth at a time, around where you tap it (`zoneBox` in `world.js`). A map can cut doors in a zone's walls (`doors` on its place), so one room file can sit on two maps. A place's paper can change with its clock (`plate.at(t)`), and the page follows.
- **Ground and water** (Plum Island, `src/engine/terrain.js`): a map can have a `land`, heights with layers printed on them and a sea under `level(t)`, so shorelines move with the clock. Each area prints its part (`drawLand(R, land)`) and stands things on it (`R.ground(x, y)`). One rule keeps the drawing simple: ground never climbs toward the viewer steeper than 0.8 a unit (QA checks); anything steeper (a jetty, a bridge) is a thing. Things in water float (`float`) or wade (`wade`). A find can be there only some of the time (`when`, with a `note` for the list), and a place can show its own clock with a skip button (`map.dial`, the tide). A dial can flip instead (`dial.flip`, Moving Day's lease clock): it jumps to the matching moment on the other side of noon and the old picture melts over the new one, so what changed jumps out; Moving Day's "what changed" finds are found that way.
- **Finding** (`game/rules.js`): finds come in kinds (`kind`: spot, poke, hard), and every area wants a spread (about half spot, a third poke, one or two hard, the goose never spot). `R.poke` is something that answers a tap (opens, says a line; draw it with `poke.k()`, marked `anim`), a find `inside` one is only tappable while it's open, and `R.decoy` is a goose lookalike that answers back. A tap goes to a find before a poke, but to a decoy when it's nearer the decoy (QA warns when a poke sits under a find's tap area). Hints are earned (3 to start, one every 3 finds) and go in two steps: a line (the find's `hint`), then a ring. A place finishes at every goose and 70% of its things. `tools/ROOM_BRIEF.md` has the details for artists.
- **Level formats:** a place's goal is every goose, unless its map has a `case` (a whodunit: evidence and curiosities, a case file, accusations, a reveal; `game/case.js`, the Manor's is `src/maps/manor/case.js`) or a `trail` (a chase: sightings of something loose, found in order, each saying who saw it go where next, the last one ending the place with the map's `finale`; `game/trail.js`, the ship's is `src/maps/cruise/trail.js`). Only the next sighting is on the list or can be tapped, and the level's art draws the quarry only there (the trail's `onStep`). The goose's trail between places will reuse it.
- **Keys and screen readers** (G5): while you play, the map is a Tab stop (`role="application"`, named and described by `nameMap` in `play.js`); focused, the arrows move it under the aim (a print mark, `#aim`), or move the aim where the map can't go, Enter taps under it, + and - zoom (`input.js`, "Keys"). A click never gives the map focus, so for the mouse the arrows still step rooms. Every area has a `describe` after its `blurb` and every place a `words.describe`: what a screen reader hears for the picture, never where a find is (QA's copy check). Arriving somewhere and a poke's line are said politely (`announce`); finds are said by the toast. Buttons are named by the words on them (WCAG's label in name): extra words for a screen reader go in an `sr-only` span, not an `aria-label` that drops the visible text.
- **Sound** (all synthesized): a place's `sound.js` gives `bed(t, here)`, a level for each loop in `game/beds.js` (the street, the sea, a dryer, a band far off) from the clock and where you are, and `muffle` for the outdoors while you're inside (beds marked `room` aren't muffled); `audio.js` mixes them, gliding. `cues` play on the clock; one with a `zone` is quieter and muffled from anywhere else. Everything sits under a honk, measured (`node tools/sound.mjs`, QA's sound check).
- **Area artists work in their own git worktrees** (the Agent tool's `isolation: "worktree"`, under `.claude/worktrees/`, ignored by git) so one artist's half-finished file never breaks another's screenshots. They copy `node_modules` in; the lead copies their area file back.
- **Layers:** `engine/` (drawing, camera, input; no game rules) → `game/` (rules, saves, sound) → `ui/` (DOM screens). Keep engine code free of game concepts like geese or scores.
- `main.js` owns routing (`#/`, `#/maps`, `#/<map>`, `#/<map>/<zone>`) and the frame loop. `game/play.js` is one controller reused across maps via `load(world)`.
- Zones must draw as pure functions of time `t`. Anything that moves is `anim: true`. See `tools/ROOM_BRIEF.md`.
- Saves: `game/store.js`, versioned (v4). Never change the shape without bumping the version and migrating (and `index.html` reads the save's key for its first paint).

## Conventions

- Match the surrounding code: plain JS, short comments that explain why, no TypeScript, no new dependencies without a good reason.
- UI copy: plain, short, funny where it fits. **No em dashes** anywhere in copy or comments.
- Colors come from `C` in `engine/art.js` or the level's style sheet (canvas), or the CSS tokens at the top of `styles.css` (DOM). Each place is one printed plate: its own paper and inks (a night is printed in dark ink, it isn't a dark mode). The picture runs to every edge of the screen, never a panel on paper: a place printed on something other than paper sets `plate.paper` to it, and the page and the browser's bars follow. QA fails raw hex colors in area files.
- Respect `prefers-reduced-motion` (the camera and CSS already do).
- Small text passes 4.5 to 1: a light ink (coral, teal, a place's own) takes its deeper shade for small labels (`--coral-text`, `--teal-text`, or `color-mix` with the ink). Run axe on what you touched (`docs/AWWWARDS.md`).
- A button holds only phrasing content (spans, not divs, headings or paragraphs): the W3C validator checks it.
- Touch targets at least 40px; everything works at 390px wide and in landscape phones.
